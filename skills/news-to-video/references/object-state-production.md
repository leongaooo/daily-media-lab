# 对象状态叙事的制作与验收

机制型资讯可用同一对象的前后状态讲清变化。每条独立新闻建立自己的对象、场景、关系和画面节奏。镜头按内容选择部署动作、互联关系、路径变化或其他形式。栏目识别、来源和底部字幕形成全期连续性。

1. 先确定观众看完能说明的关系。逐幕记下主体、前态、触发、后态、结果和限制。核验资料支持哪些动作，实际确有现场或型号依据且用途获准时优先采用原素材。原创 SVG、2D 或三维示意应保留相应标签。
2. 当位置、路径与条件对理解最重要时，用自定义 React／SVG 舞台表现。需要真实尺度、空间遮挡、材质或摄影信息时，用 Blender 完整镜头。两者沿用固定字幕与同一合成入口。选择理由写入现有制作计划。
3. 按最终干声的实际 cue 编译帧。对每个关键动作写出真实消费位置、可观察的前后变化和对应证据。自定义 `Stage.tsx` 读取其 scene-local 整数帧，混音使用加上场景起点的全局帧。句内导演时间是编排值，词级同步需要额外实测。开篇配乐和章节声音随语义进入、退出，留住口播清晰度。
4. 整期扩展前先完成约 20–30 秒的带声预演，按完整语义调整窗口。窗口绑定母版哈希和样本范围，音效与环境声保持独立文件身份。抽查实际渲染画面的前、中、后态，并检查关系是否容易复述、素材是否体现于画面、字幕保护区与试听表现。发现误读则修正对应层再扩展。
5. 整片交付回执关联媒体哈希、实际消费者、事件帧、声音资产、代表帧以及未实测层。数字解码、静帧、连续声画、人工验收、跨设备试听与受众表现各按已有证据登记。用户明确通过本期人工验收时保留原话以及成片版本，逐项试听和目标受众效果按实际记录。

优先复用对象与状态解释方式、预演窗口和验证方法。每期的颜色、空间、画面素材和声纹按题材及许可决定。可以从[可执行合成示例](../assets/object-state-preview/README.md)核对已有消费者。将短段与整片的输入配置和资产分别保存，可复核每次混音的音轨身份。声音或画面调整时重跑受影响的检查。

正式交付接入[日更成片回执](editorial-handoff.md#日更成片回执)，按实际帧和播放器结果登记预演与整期证据。
