# 两个技能的协作约定

采编端决定“说什么、依据是什么、图片要表达什么”；制作端决定“如何把已经确认的内容做出来”。两者通过可读剧本和制作 JSON 交接，当前不是任意 Markdown 自动导入器。

制作统一使用 `daily_editorial` 横屏 1920×1080、24fps 和 y904—1080 固定底部字幕轨。新项目设置 `director_contract_version=1`，按[视觉导演约定](../skills/news-to-video/references/visual-director.md)定义各新闻的 `story_world` 与逐幕 `visual_goal`。保留已确认的 `spoken` 和声音身份；镜头按实测字幕切换。每期同一生成目录累计最多 10 次付费生图尝试，失败/未确认计入，已核验缓存不计。另交故事世界报告、动效报告和人工核验的可复用资产清单。

## 一次制作

1. 采编端读取根目录 `news/` 的来源地图、七日台账和路线图跟踪，打开当篇一手材料核验日期、状态与范围。
2. 写成一期多板块剧本。每幕包含口播、屏幕文字、证据 ID、`asset_id`、视觉类型；生成图片写出完整正负提示词。
3. 制作端保留原稿快照，按 `references/script-handoff.md` 手工规范化到项目格式，建立 `script-map.json`。
4. 生图前把正负提示词合并到实际发送的 `image_generation.prompt`。同一素材 ID 只生成一次；看图后记录实际尺寸、裁切和示意边界。数据关系用 SVG/图表表达。
5. 对接本地声音环境。字幕 `text` 与发音 `spoken` 分工；合成、变速、降噪后测量真实时长，建立连续字幕与镜头时间线。
6. 配乐按实际讲话活跃段配平与避让。输出公开署名；声音与画面均核验后交付一个成片。
7. 核对完整解码、字幕覆盖、逐幕画面、事实映射；另做人耳试听。明确“已生成”“已检查”“已发布”的区别。

## 交接表

| 内容 | 采编端提供 | 制作端保留/验证 |
| --- | --- | --- |
| 事实 | 来源、日期、发布方、状态与限制 | 口播/字幕不擅自加强结论 |
| 图片 | 素材 ID、目标、提示词、示意性质 | 本地素材绑定、看图记录、来源与授权 |
| 图解 | 有证据的关系和节点 | SVG/PNG、实际画面中的文字与边界 |
| 声音 | 原口播、术语读法与数字 | 实测长度、干声/混音、发音核对 |
| 节目 | 板块与幕序 | 一期一条时间线；拆片需显式要求 |

缺图、错误声音或不支持画幅不能静默回退并宣称完成。只要剧本不读取密钥、不发起生图或配音；只要图片则不启动成片渲染。
